# ADR-0064: Two-region deployment and verification record

**Status:** In progress. Deployment and browser verification are not yet complete.

## Context

- The requested outcome is an end-to-end `azd up` deployment in two regions, followed by every existing Playwright suite and screenshots.
- The starting revision is `a9aa6f6`. The checkout was clean on `main`.
- Azure subscription discovery returned enabled subscription `ME-MngEnvMCAP340513-anbossar-1` (`6fc552c5-06b6-43d7-ac70-2f1eda1be033`). ARM tenant discovery returned `anbo`, tenant `46693104-8c42-47b7-98e3-985ed39402f6`, domain `mngenvmcap340513.onmicrosoft.com`.
- The existing `azd` environment is `alwaysonn`, with the matching subscription. Initial preflight found no saved location or tenant; the observed deployment command pins the environment, subscription, and location explicitly.
- The user chose to keep all work on `main` and authorized commits and pushes after fixes are confirmed working and this record is updated.

## Decision

- Use the existing `azd` lifecycle. Keep deployment fixes in Bicep, hooks, or manifests so a later `azd up` reproduces them.
- Target `swedencentral` and `eastus2`, with final service-preview and native deployment gates. The user approved checking outside Europe and admitting D/E generation v6 workers in East US 2. Keep the same anbo/MCAPS target and architecture; leave partial resources untouched.
- Retain existing v4/v5 worker selectors and add only v6, preserving CPU, family, spot, architecture, and security constraints. Prefer an existing regional override; if the shared base selector owns the change, it also broadens future deployments using that base. No unrelated production deployment is authorized.
- Give one app session exclusive Azure deployment ownership. Give parallel fix sessions non-overlapping file ownership after infrastructure is available. The coordinator owns this ADR and Git checkpoints.
- The deployment owner freezes build inputs while packaging images. Record the source checkpoint and deployed image identity before claiming a fix is live.
- Run full Playwright suites against deployment-derived application and API URLs. Production projects that filter to smoke tests are insufficient.
- Verify real application operations through Front Door and collect evidence for both stamps. Health probes alone do not establish success.
- Use Codex for implementation and an opposing model family for disconfirming review.
- Assess session activity every 30 minutes using the saved coordinator automation. An idle session is not by itself a failure.

## Consequences

- **Positive:** Deployment failures, workarounds, proof, and confirmed fixes have one versioned record.
- **Negative:** Sharing `main` requires explicit file ownership and packaging freezes. Unverified work remains uncommitted.
- **Negative:** The failed Germany attempt left partial resources. The user approved leaving them untouched while moving the active second stamp; their costs remain until separately authorized cleanup.
- **Negative:** A second region outside Europe can increase cross-region latency to the Sweden-hosted shared services. The user approved that geography expansion without changing the architecture.
- **Rejected:** Parallel infrastructure mutations, smoke-only verification, health-only acceptance, and manual cloud patches outside the reproducible deployment path.
